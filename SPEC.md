# Спецификация продукта

## 1. Цель

Создать жизнеспособное локальное-first веб-приложение, которое даёт пользователю единую и проверяемую картину личных финансов: фактические активы и расходы, обязательные будущие платежи, вклады, прогноз состояния, финансовые цели и объяснимые рекомендации.

Главный критерий ценности: пользователь в любой момент понимает, сколько у него денег, куда они уходят, что произойдёт при сохранении текущего поведения и что нужно изменить для достижения выбранной цели.

## 2. Пользователи и режимы

### MVP

- Один локальный инстанс, один мастер-пользователь.
- Вход по email и паролю.
- Интерфейс на русском языке; архитектура готова к i18n.
- Основная валюта пользователя задаётся в профиле.

### Следующий релиз

- Несколько пользователей только по приглашению/allowlist.
- Подтверждение email и восстановление пароля через SMTP.
- Развёртывание на сервере с TLS и внешним или локальным LLM.

## 3. Функциональные требования

### 3.1 Счета и операции

- Создание счетов типов: наличные, банковский, накопительный, вклад, иной актив.
- Начальный остаток оформляется отдельной проводкой.
- Доход, расход и перевод между счетами.
- Категории и древовидные группы категорий для отчётов.
- Комментарий, дата/время, валюта, сумма, теги и источник операции.
- Фильтры, поиск, пагинация и экспорт CSV.
- Исправление операции без потери истории; физическое удаление проведённой операции запрещено.

### 3.2 Регулярные платежи

- Шаблон дохода/расхода/перевода с периодичностью, датой следующего срабатывания, часовым поясом и необязательной датой окончания.
- Поддержка минимум: ежедневно, еженедельно, ежемесячно и ежегодно.
- Правило для несуществующего дня месяца явно задаётся: последний день месяца либо пропуск.
- Повторный запуск worker не создаёт дубль.
- Пользователь видит предстоящие операции и может приостановить правило.

### 3.3 Вклады

- Сумма, валюта, номинальная ставка, схема капитализации, срок, дата открытия.
- Пополнения и частичные снятия как отдельные денежные потоки.
- Плановые и фактические начисления процентов.
- Расчёт текущей стоимости, начисленного дохода и эффективной доходности.
- Явные правила округления, досрочного закрытия и налогообложения; в MVP налог можно задать параметром, но нельзя «угадать» по стране.

### 3.4 Аналитика

- Расходы и доходы по периоду, категории и группе.
- Денежный поток, изменение капитала, доля обязательных расходов, savings rate.
- Сравнение периодов и обнаружение аномальных изменений детерминированными правилами.
- Все показатели воспроизводимы из проводок.

### 3.5 Прогнозы

- Прогноз на произвольную дату, а не только «через год».
- Базовый сценарий строится из текущих остатков, регулярных операций, параметров вкладов и прозрачной оценки нерегулярных трат.
- Пользователь может создать сценарии и изменить допущения: доход, инфляция, расходы, разовые события, ставка.
- Результат показывает итог, помесячный ряд, использованные допущения и диапазон неопределённости.
- Прогноз не выдаётся за гарантию.

### 3.6 Финансовые цели

- Цель: название, сумма, валюта, срок, уже накопленная сумма, приоритет и связанный счёт.
- Расчёт необходимого ежемесячного взноса и ожидаемой даты достижения.
- Сравнение нескольких стратегий накопления.
- Предупреждение о недостижимой цели с числовым объяснением.

### 3.7 LLM-советник

- Советы формируются только из агрегированных метрик и детерминированных расчётов.
- LLM объясняет наблюдения, предлагает варианты и задаёт уточняющие вопросы; она не изменяет финансы сама.
- Ответ имеет структурированный контракт, содержит факты-основания, допущения, уровень уверенности и дисклеймер.
- Передача сырых транзакций внешнему провайдеру выключена по умолчанию и требует явного согласия.
- Приложение полноценно работает при выключенной или недоступной LLM.

## 4. Нефункциональные требования

- Финансовые значения хранятся без binary float; правила округления задокументированы и тестируются.
- Все пользовательские данные изолированы по владельцу.
- Мутации имеют idempotency key там, где возможен повтор запроса или задания.
- Миграции БД обратимы настолько, насколько это безопасно для данных.
- Секреты приходят только через окружение/secret manager и не попадают в логи.
- API документируется OpenAPI-схемой; LLM вызывается через OpenAI-compatible API.
- Логи структурированы, содержат correlation ID, но не пароли, токены и чувствительные финансовые детали.
- Есть резервное копирование и проверенная процедура восстановления PostgreSQL.
- Основные пользовательские сценарии работают на desktop и mobile шириной от 360 px.

## 5. Ключевые пользовательские сценарии

1. Первый запуск → мастер-аккаунт → валюта и часовой пояс → первый счёт → начальный остаток.
2. Добавить расход «продукты» → увидеть изменение баланса и отчёта.
3. Создать ежемесячную подписку → увидеть ближайшее списание → дождаться/запустить обработку без дубля.
4. Создать вклад с капитализацией и пополнением → сверить график и доходность.
5. Выбрать дату прогноза → изменить сценарий → сравнить результат.
6. Создать цель → увидеть необходимый взнос и варианты действий.
7. Запросить совет → получить объяснение на основе показанных метрик → увидеть, что LLM ничего не изменила.

## 6. Вне MVP

- Прямое подключение к банкам и автоматический импорт банковских данных.
- Торговля ценными бумагами, криптокошельки и котировки в реальном времени.
- Полноценный бухгалтерский или налоговый учёт для конкретной юрисдикции.
- Автоматическое выполнение финансовых действий по совету LLM.
- Совместные семейные бюджеты и сложные роли организаций.
- Нативные мобильные приложения.

## 7. Definition of Done продукта

- Все семь ключевых сценариев проходят как автоматические E2E-тесты и вручную по runbook.
- Балансы и прогнозы сверены с независимыми эталонными примерами.
- Повторная доставка запросов и заданий не создаёт двойных операций.
- Проверены изоляция пользователей, rate limits, обработка сессий, резервное копирование и восстановление.
- `docker compose` поднимает core-стек без LLM и отдельным профилем поднимает локальный vLLM.
- Свежая машина может запустить проект по README без неописанных ручных шагов.
- В репозитории нет секретов и критических/высоких известных уязвимостей.
