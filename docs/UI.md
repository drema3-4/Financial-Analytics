# Визуальная система frontend

## Направление

Financial Analytics выглядит как спокойный личный финансовый инструмент, а не как
универсальная административная панель. В основе — редакционная композиция: тёплый фон
«бумаги», отдельные светлые рабочие поверхности, тёмный хвойный цвет для основных действий
и приглушённый янтарный для внимания. Крупные заголовки и короткие пояснения дают контекст,
а таблицы и числовые блоки остаются компактными и выровненными.

Интерфейс не имитирует банковское приложение и не использует декоративные графики как
доказательство «аналитики». Цвет сообщает состояние, но никогда не является единственным
сигналом. Числа получают табличные цифры; денежная сумма всегда показывается вместе с
валютой. Для первой версии используются системные шрифты с полноценной кириллицей и без
сетевой загрузки: выразительный serif-stack для главных заголовков и нейтральный sans-stack
для данных и управления.

## Принципы

1. **Сначала смысл.** На экране есть один главный вопрос и одно визуально главное действие.
2. **Плотность без тесноты.** Списки и таблицы используют компактный вертикальный ритм, но
   интерактивные цели имеют размер не менее 44×44 px на touch-устройствах.
3. **Слой за слоем.** Фон, рабочая поверхность и поднятый dialog различаются цветом,
   границей и только затем тенью. Постоянная сетка карточек не используется.
4. **Доверие к цифрам.** Денежный ввод хранится как строка, локальный разделитель переводится
   в decimal contract без JavaScript `number`, а ошибки находятся рядом с полем.
5. **Предсказуемые состояния.** Loading сохраняет геометрию, empty объясняет следующий шаг,
   error называет безопасное действие, session-expired возвращает ко входу без потери
   объяснения.
6. **Доступность по умолчанию.** Семантические landmarks и labels, видимый focus ring,
   контраст не ниже WCAG AA, полная клавиатурная навигация и уважение `prefers-reduced-motion`.

Chart palette не повторяет семантику ошибок буквально: `#174f3f`, `#c8782a`, `#466f91`,
`#8a5d78`, `#65724a`, `#a94f45`. Серии дополнительно различаются подписью/маркером; красный и
зелёный не используются как единственная пара различий.

### Типографика и геометрия

- Display: `ui-serif, "PT Serif", Georgia, serif`, 700, line-height `1.05`.
- Interface/data: `Inter, "Golos Text", "Segoe UI", Arial, sans-serif`, line-height `1.5`.
- Money/data: `font-variant-numeric: tabular-nums lining-nums`.
- Размеры текста: `0.75`, `0.875`, `1`, `1.25`, `clamp(2rem, 6vw, 4.5rem)` rem.
- Шаг пространства: 4 px; рабочие значения 8/12/16/24/32/48/64 px.
- Радиусы: 8 px для controls, 14 px для surfaces, 24 px для крупных onboarding panels.
- Focus: внешний ring 3 px с offset 2 px; `outline` не удаляется без равноценной замены.

## Компоненты и состояния

- `Button`: primary, secondary, quiet и danger; pending сохраняет ширину и сообщает состояние.
- `InputField`, `MoneyInput`, `DateControl`: всегда имеют видимый label, hint/error связываются
  через `aria-describedby`. Денежный input использует `inputmode="decimal"` и показывает
  локальный пример.
- `Dialog`/`Drawer`: нативный `<dialog>`, закрытие по Escape, возврат focus инициатору; drawer
  становится нижним листом на узком экране.
- `DataTable`: таблица на широком экране и семантический list с теми же полями на mobile.
- `LoadingState`, `EmptyState`, `ErrorState`: самостоятельные region/status, не случайный текст.
- `Toast`: неблокирующее подтверждение через polite live-region; ошибки формы остаются рядом с
  источником и не полагаются только на toast.

## Layout и адаптивность

- Минимальная поддерживаемая ширина — 360 px без горизонтальной прокрутки страницы.
- До 719 px shell использует компактную верхнюю панель и нижнюю навигацию; dialogs занимают
  почти весь viewport с безопасными отступами.
- От 720 px навигация становится боковой, контент ограничивается читаемой шириной, а формы
  могут использовать две колонки.
- От 1180 px увеличивается воздух вокруг главного полотна, а не плотность данных.
- Анимации ограничены opacity/transform и полностью отключаются при
  `prefers-reduced-motion: reduce`.

## Первый запуск

Незалогиненный пользователь видит отдельные маршруты входа и создания локального
пространства. Мастер первого запуска собирает email/пароль, затем базовую валюту,
locale/timezone, создаёт master session и предлагает первый счёт с необязательным начальным
остатком. После успешной записи первого счёта пользователь попадает на dashboard. Если
session уже существует, bootstrap профиля и списка счетов направляет пользователя сразу в
правильную точку; истёкшая session один раз обновляется через refresh cookie, после чего UI
показывает явное сообщение и возвращает ко входу.

## Финансовое рабочее пространство

- Dashboard показывает server-derived capital/cash flow, обязательства, цели, счета и
  `data_through`; multi-currency режим всегда предупреждает, что суммы без FX не объединены.
- Journal сохраняет фильтры в query key, использует cursor pagination и подтверждает сторно
  как новую обратную проводку с влиянием на баланс и отчёты. Физического удаления в UI нет.
- Recurring preview показывает локальное и UTC-время, IANA timezone и явную missing-day policy.
- Deposit valuation, analytics и forecast визуализируют только ответы API. Каждому SVG/chart
  соответствует таблица; planned/actual, assumptions и uncertainty читаются без графика.
- Advice отделён визуально от финансовых команд: suggestions названы вариантами, evidence
  имеет якоря, consent действует на один запрос, confidence соседствует с disclaimer.
- Финансовые mutation не optimistic. После ответа server соответствующие server-state queries
  инвалидируются; pending/error остаются рядом с инициировавшей формой.
