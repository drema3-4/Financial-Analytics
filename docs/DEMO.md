# Демонстрационный стенд

Стенд `financial-analytics-demo` содержит только вымышленные данные и собственную БД.
Основной Compose project `financial-analytics` и его volume не используются для наполнения.
Web: <http://127.0.0.1:4174>, API: <http://127.0.0.1:8002/docs>, vLLM health:
<http://127.0.0.1:8003/health>. Все опубликованные порты привязаны к loopback.

Демо-логин: `demo@example.test`. Независимый случайный пароль находится в ignored `.env.demo`
в поле `DEMO_PASSWORD`; credentials и отчёты не входят в Git. Это master только демонстрационной
БД. На другом hostname браузер использует отдельные cookies; для показа используйте `127.0.0.1`.
Для одновременного входа в основной и демонстрационный стенды используйте отдельные профили
браузера: cookies одного hostname не разделяются по порту. Встроенный браузер этой демонстрации
использует собственную сессию.

## Запуск существующего стенда

Из корня проекта:

```powershell
docker compose -p financial-analytics-demo --env-file .env.demo -f compose.yaml -f compose.demo.yaml --profile local-llm up -d --wait --wait-timeout 600
```

На RTX 3050 запускайте один GPU engine одновременно. Если основной vLLM запущен, перед demo
остановите его: `docker compose --profile local-llm stop vllm`. Основной core может работать
параллельно: его порты отличаются от demo.

Остановка с сохранением данных:

```powershell
docker compose -p financial-analytics-demo --env-file .env.demo -f compose.yaml -f compose.demo.yaml --profile local-llm stop
```

## Воспроизведение с нуля

Нужны Docker Compose v2 с поддержкой `!override`, доступная NVIDIA GPU, основной model cache
`financial-analytics_huggingface_cache` и Python environment из README. При отсутствии cache
сначала создайте пустой volume командой `docker volume create financial-analytics_huggingface_cache`;
при старте vLLM загрузит закреплённую модель по обычному HTTPS.

```powershell
.\.venv\Scripts\python.exe scripts/seed_demo.py --prepare-environment --as-of 2026-10-19
docker compose -p financial-analytics-demo --env-file .env.demo -f compose.yaml -f compose.demo.yaml --profile local-llm up -d --build --wait --wait-timeout 600
.\.venv\Scripts\python.exe scripts/seed_demo.py
```

На Linux/WSL используйте `.venv/bin/python`. Подготовка сохраняет существующую `.env.demo`;
она не перезаписывает пароль или исходную дату. Все financial money/rate fixtures — decimal
strings; синтетическая вариация сумм использует `Decimal`. Дата истории явно задана в
`DEMO_AS_OF`, а операции и schedules — в `Europe/Saratov` с явным UTC offset.

Seed работает только с `http://127.0.0.1:8002` и обозначенным demo-логином. Он регистрирует
первый demo master обычным bootstrap либо входит в уже созданный demo-аккаунт. Наполнение
проходит через действующие API, CSRF, idempotency и audit. Регулярная история создаётся
настоящим worker, поэтому фиксированные траты не попадают повторно в irregular baseline.

Повторный запуск проверяет полный fingerprint журнала и не добавляет дубли. Если после
изменения исходного seed появился idempotency conflict, сначала изучите разницу данных;
скрипт не сбрасывает БД и не переписывает проведённые операции. Для наполнения без LLM-запросов
используйте `--skip-advice`; полный запуск также обновляет снимки советов.

## Что подготовлено

История на 2026-10-19: апрель–октябрь, 176 операций, четыре обычных счёта, два вклада,
15 категорий в четырёх группах, девять регулярных правил, пять целей и шесть сохранённых
сценариев. Есть переводы, капитализация, близкое погашение, крупный отпуск, ремонт и исправление
чека через reversal с сохранением истории. Все ставки являются параметрами вымышленного примера.

| Цель | Что показывает |
|---|---|
| Подушка 300 000 ₽ | первый приоритет и достижимый взнос |
| Отпуск 180 000 ₽ | конкуренция целей за будущий денежный поток |
| Ноутбук 240 000 ₽ до конца года | амбициозный срок и shortfall |
| Первоначальный взнос 2 500 000 ₽ | явный большой дефицит |
| Обучение 90 000 ₽ | already achieved |

Сценарии: текущие привычки; расходы −15%; доход +20% и расходы +5%; доход −20% и расходы +15%
с инфляцией 10%; разовая премия 180 000 ₽; покупка техники 220 000 ₽. Они меняют только прогноз.

## Порядок показа

1. **Обзор**: показать капитал, доходы/расходы и ближайшую часть зарплаты.
2. **Аналитика**: переключить период на сентябрь, затем октябрь; объяснить влияние отпуска и
   ремонта, категории и долю обязательных расходов.
3. **Операции**: найти «Чек кафе», показать исходную запись, reversal и замену; переводы
   не являются доходом или расходом.
4. **Регулярные**: зарплата двумя частями, аренда, подписки и перевод в отпускную копилку.
5. **Вклады**: открыть вклад подушки, график и начисления; затем короткий вклад к погашению.
6. **Цели**: сравнить достигнутую цель, подушку и проблемный срок покупки ноутбука.
7. **Прогноз**: отметить экономию, карьерный рост и стресс в блоке сравнения.
8. **Советник**: спросить о риске цели первого приоритета, показать evidence и ограничения.

Числовые планы и сравнения рассчитывает API. LLM только объясняет переданные факты, не
выполняет операции и не имеет доступа к внешним сервисам через tools. Для пяти целей demo
использует context 4096, non-thinking и одну sequence; provider timeout 120 секунд без retries.

Полный seed запрашивает три совета: о приоритетах в базовом плане, об экономии и о стрессовом
сценарии. Ответы не сохраняются приложением; seed сохраняет демонстрационные снимки отдельно:

- `generated-reports/demo/SHOWCASE.md` — маршрут показа, сравнения и полученные объяснения;
- `comparison.json` — полные детерминированные результаты всех вариантов;
- `advice-1.json`–`advice-3.json` — ответы со всеми evidence, статусом и временем;
- `manifest.json` — идентификаторы синтетических сущностей и число операций.

Браузерный советник пока запрашивает базовый план на год. Советы для сохранённых сценариев
вызываются существующим API с `scenario_id`; снимки доступны в SHOWCASE. На GPU ответ может
занимать до двух минут; перед показом запустите запрос, а подготовленные снимки можно
использовать для показа уже полученного результата. `configured` означает настройки,
а успешный полный ответ имеет статус `available`.
